## 1. 원본에서 한 번 양자화

- **재료**: 로더는 지금처럼 `VarBuilder::from_mmaped_safetensors(F32)`로 연다. 배분이 양자화하라는 선형 가중치는 같은 파일을 CPU 쪽으로
  한 번 더 매핑한 `MmapedSafetensors`에서 F32 값을 읽어 인코더에 넣고, GGML 블록 바이트로 `QTensor`를 만든다. 배분이 F32 인 가중치는
  예전 그대로 `candle_nn::linear`로 올라가 이전 모델과 **비트까지 같다**(시험 `a_quantized_linear_is_close_and_the_f32_plan_is_the_old_layer`).
- **인코더**: blueprint-sandbox 에서 쓴 GGML 인코더를 옮겼다(블록 중요도 `rms(블록) + |x|`, 대칭 후보 19개 · 비대칭 21개의 가중 최소제곱,
  묶음 척도 F16 올림, 짝수 반올림). quant.py 값 대조 · candle 역양자화로 다시 읽기 · candle 자체 양자화보다 오차가 작음을 시험한다.
- **곱셈**: `QLinear`가 `QMatMul::forward_exact`로 곱한다(활성값을 양자화하지 않고 F32 로 누산). Vulkan 은 포크가 Q8_0 만 장치에서 곱하고
  K 형식은 호스트로 보내므로 Vulkan 에서는 K 형식 칸이 Q8_0 이 된다(`QuantPlan::for_device`).
- **올리는 시간 [측정]**: Q8_0 으로 SigLIP2 선형 가중치 710.1 → 188.6 MB 를 2.5 – 2.8 s 에 양자화한다(올리기 전체 4.5 – 4.9 s, F32 는 2.0 – 3.0 s).
  TIPSv2(깊이 머리만)는 358.6 → 95.3 MB 를 1.2 – 1.4 s(전체 1.6 – 1.8 s, F32 0.3 – 0.7 s). rayon, `noto-ml` opt-level 3.
  지시문 피라미드도 비슷하다(149.2 MB · 2.3 – 2.8 s, 76.7 MB · 1.1 – 1.4 s).
- **ROCm 의 양자화 행렬곱 [직접: 포크 소스]**: 고정된 포크(2191c7a)의 ROCm 백엔드는 입력이 8행 이하면 F32 mat-vec 커널, 그보다 많으면
  가중치를 F32 타일로 풀고 rocBLAS F32 GEMM 을 부른다. 비전 트랜스포머의 패스는 늘 200 행이 넘으므로 **양자화는 상주 VRAM 만 줄이고
  계산은 F32 GEMM 그대로**다 — 지시문의 "메모리 대역폭 50 % 절감"은 이 백엔드에서 일어나지 않는다. 실측도 같다(§4: 밀집 패스 70.1 → 71.4 ms).

## 2. 텍스트 토큰 표의 비대칭 상주

`text_model.embeddings.token_embedding.weight`는 256,000 × 768 F32 = 786.4 MB 로 SigLIP2 전체(1.50 GB)의 52.4 %다 [측정: 머리말].
텍스트 타워는 문구가 처음 나올 때만 돌고(문구 은행이 벡터를 디스크에 둔다), 그때 필요한 행은 문장의 토큰 수십 개다.

- 표는 매핑된 파일에 그대로 둔다(장치 0 MB). 장치에는 쓰는 행만 모은 작은 표와 "전역 번호 → 행" 색인을 둔다. 문장의 토큰 중 표에 없는 것이
  있으면 그 행을 파일에서 읽어 붙인 뒤 같은 `index_select`로 고른다. 같은 F32 바이트를 같은 연산으로 고르므로 **벡터가 전체 표와 비트까지 같다**
  — 그래서 문구 은행의 지문을 바꾸지 않는다.
- 미리 올릴 문장(`noto_runtime::vocab_texts`): 세계 사전의 모든 문자열, 비전 문구 · 배경 문구에 템플릿 6개를 씌운 문장, 물류 사전의 프롬프트와
  한 · 영 이름, 명령 어미(`noto_search::tails::VERB_TAILS`). 앱은 SigLIP2 를 올린 직후 이 문장으로 표를 채운다(`src-tauri/src/state.rs`).
- 토크나이저는 원본 그대로라 `<unk>`가 새로 생기지 않는다(Gemma 는 바이트 폴백).

`ml_vocab_check` [측정]:

| | 값 |
|---|---|
| 미리 올린 문장 | 1,188 개 → 986 행, `<unk>` 0 개 |
| 장치의 토큰 표 | 988 / 256,000 행, **3.04 MB** (전체 표 786.4 MB, −99.6 %) |
| 자유 명령 5개 뒤(한국어 4 · 영어 1) | 1,000 행 (쓰는 중에 더한 행 12) |
| 전체 표와 같은 비트의 벡터 | **1,193 / 1,193** |
| 1,193 문장 임베딩 시간 | 3.9 s (전체 표 3.6 s) |

지시문의 "8,192 또는 16,384 행 타일 정렬 · 64 의 배수 패딩"은 행렬곱이 아니라 행 고르기(`index_select`)라 이득이 없어 하지 않았다.

## 3. 지문 · 모드

- **지문**(`Siglip2::fingerprint`)은 문구 은행(`PhraseBank`)의 열쇠이고, 그 벡터는 텍스트 타워만 만든다. 그래서 텍스트 타워의 배분(`st.*` 묶음)이
  지문에 들어간다. 비전 타워만 양자화하거나 토큰 표 방식이 달라도 문구 벡터는 같으므로 지문도 같다(시험 `ml_vocab_check`).
- **의미 위치 모드**: `SiglipLocator`의 모드가 `LocateCfg::mode()` 뒤에 비전 타워의 적재 방식(`+q-<배분>`, Fused QKV 면 `+fqkv`)을 붙인다
  (`siglip2-dense+bg+pyr+q-q8`). 보정표 · SDS 위치 범위가 이 모드로 갈린다. `LocateCfg::from_mode`는 이 부분을 모델 정보로 보고 건너뛴다.
- **깊이 모드**: `TipsDepth`의 모드가 `tipsv2-b14-dpt+q-<배분>`(정렬하면 `…+ground`)이 되어 SDS 깊이 범위(축척 · AbsRel 기준선)가 갈린다.
- `data/ml_calib.json`은 지금 비어 있다(`[]`): 하네스는 늘 맞춤 시드에서 보정표를 다시 맞추므로 `MLAB_REFIT`이 없어도 배분마다 따로 맞는다.

## 4. 묶음별 민감도 (`ml_quant_screen`)

F32 모델을 한 번 올려 기준 출력을 만든 뒤, 배분마다 모델을 원본에서 양자화해 올리고 같은 키프레임(하네스의 장면 · 렌더 · WebP q70)을 돌린다.
L1 은 하네스의 런타임 경로(배경 소프트맥스 `Contrast` + 피라미드 격자), L2 는 하네스의 v1.0 포트(읽어 내기 tanh GELU, 짧은 변 24 패치)다.
보정 ECE 는 맞춤 시드(홀수)에서 피크의 Platt 를 맞추고 평가 시드(짝수)에서 15칸 ECE 를 잰 값이다.

## 5. 결정 — GPU 기본 배분: 모든 선형 가중치 Q8_0

수용 기준 안에 든 배분은 **모든 선형 가중치 Q8_0** 하나였다(§4). 지시문의 4계층 표는 두 모델 모두 기준을 넘었고(존재 AP −0.010, δ1 −1.4 %p),
그 손상의 거의 전부가 Tier 4(중간층 fc1 Q4_K)다. Q6_K · Q5_K 로 더 내릴 수 있는 묶음(TIPS 중간 블록 주의 · fc2)은 아끼는 양이 9 MB 남짓이라 넣지 않았다.

- `QuantPlan::for_load`: `NOTO_QUANT`가 없으면 **GPU 는 `q8`, CPU 는 `f32`**. CPU 에는 지킬 장치 메모리가 없고, CPU 의 `forward_exact`는 블록
  가중치를 부를 때마다 F32 로 풀어 오히려 느리다. Vulkan 은 Q8_0 만 장치에서 곱하므로 `q8`이 그대로 맞는다.
- 지문(문구 은행): 텍스트 타워가 Q8_0 이 되므로 지문이 바뀌어, 업그레이드 뒤 처음 켤 때 문구 벡터를 한 번 다시 만든다(몇 초).
- 모드: `siglip2-dense+…+q-q8`, `tipsv2-b14-dpt+q-q8`. SDS 위치 · 깊이 기준선은 새 모드로 다시 쌓인다(F32 의 기준선과 섞이지 않음).

## 6. 양자화하지 않는 것

- **Granite TTM-R3** (1.45 M 매개변수, 5.9 MB): 분위수 머리가 이미 `Vec<f32>`로 꺼내져 CPU 에서 돈다. F32 그대로.
- **SAM (MobileSAM, TinyViT-5M)**: 10.1 M 매개변수(40.6 MB) 중 이미지 인코더 선형층(블록 MLP · 주의 qkv · proj)이 4.7 M(18.7 MB), 마스크 디코더가
  3.5 M 이다 [측정: 머리말]. 지시문 배분대로 해도 약 13 MB 를 아끼는데, 그러려면 candle-transformers 의 TinyViT 를 `QLinear`로 다시 짜야 한다.
  F32 그대로 둔다. SAM ViT-B(375 MB)는 앱이 받지 않는 선택 모델이라 이번 범위 밖이다.
- **합성곱**(TIPSv2 DPT 재조립 · 융합, SigLIP2 패치 투영은 선형이지만 화소 첫 투영): candle 에 양자화 합성곱이 없고, 지시문도 F32/BF16 보호층으로 둔다.
- **정규화 · 바이어스 · 위치 · LayerScale(ls1 · ls2) · 온도 · bin 분류기**: 늘 F32.

  절대 시간은 비관적이고, 실행끼리 비교한 시간(§5 의 전체 하네스)은 판단에 쓰지 않는다.
