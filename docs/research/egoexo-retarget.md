# 다중 시점 손 · 물체 복원, 이종 기구학 리타겟팅, 조건부 관측 합성 — 지시문 대조와 실측

조사일 2026-11-14. 이 문서에서 온 코드: `crates/noto-core/src/fit3.rs`(유사 변환 · PA-MPJPE), `handfit.rs`(Stage 1), `tactile.rs`
(Stage 2), `act/retarget.rs`, `crates/noto-vision/src/egoexo.rs` · `motion_iou.rs`, `crates/world-sim/src/render.rs`
(`render_boxes_only` · `render_scene_only` · `NEUTRAL_BG`), `crates/noto-data/src/trajectory_export.rs`, 벤치
`crates/noto-runtime/tests/egoexo.rs` · `retarget.rs`.

표기는 [`actions.md`](actions.md)와 같다: **[직접]** 출처에 인쇄된 값, **[유도]** 계산, **[추정]** 출처를 찾지 못해 정한 값,
**[측정]** 이 저장소의 하네스가 잰 값.

**결론**: 네 모듈의 수식을 엔진에 맞춰 구현하고 시뮬레이터에서 쟀다. 머리 카메라에 바깥 고정 카메라 두 대를 융합하면
**손목 위치는 32 % 좋아지지만**(1.34 → 0.91 cm), 손가락 모양(PA-MPJPE)과 접촉 패드는 바깥 카메라가 충분히 정밀할 때만 좋아진다
(320 px 에서 1.41 → 1.33 cm · F1 0.72 그대로, 1280 px 상당에서 1.13 cm · F1 0.81). 한 번 기록한 들기를 다른 몸에 옮기면 손가락 수보다
**몸의 크기가 먼저 갈린다**(시연 몸 손목 목표 도달 73 %, 소형 몸 9 %). 엔진의 서보는 1차 지연이 아니라 계산 토크 제어라 지시문의
위상 선행 라벨은 오히려 추종 오차를 4 배로 키운다 — 서보 모델별로 정확한 역을 쓰게 했다. 영상 생성 모델(4.2)은 이 저장소에 없어
세 조건 스트림(정적 배경 · 로봇만 · 문구)까지만 만든다.

## 1. 측정 — 다시점 손 자세와 접촉 (`tests/egoexo.rs`)

통나무 · 돌 · 소포 × 시드 3 개, 걷는 몸(손가락 5 개)이 물건을 손에 든 모든 틱(285 프레임). 정답은 월드가 손에 그리는 손가락 링크
(`own_arm_boxes`)의 관절점 20 개(오른손). 머리 카메라와 바깥 카메라 두 대(물건에서 약 1.7 – 1.9 m)가 각자의 렌더에서 그 점을 볼 때만
관측하고, 관측은 시선 방향으로 σ_Z = Z²·0.27 px / (f·b)(b = 0.06 m), 가로로 Z·1 px / f [추정: 키포인트 퍼짐]의 노이즈를 갖는다.
320 × 213 화면(f = 228 px). 같은 렌더에서 노이즈를 5 번 뽑았다(735 경우). Stage 1 은 두 추정 모두 점마다 정보 행렬로 가중한다 [측정].

| | 머리 카메라만 | 세 시점 융합 (바깥 320 px) | 세 시점 융합 (바깥 1280 px 상당) |
|---|---|---|---|
| 손목 오차 평균 (중앙) | 1.34 cm (0.45) | **0.91 cm (0.32)** | 0.87 cm |
| MPJPE | 1.75 cm | 1.53 cm | — |
| PA-MPJPE 평균 (중앙) | 1.41 cm (1.12) | 1.33 cm (1.03) | 1.13 cm |
| 접촉 패드 F1 (Stage 2, 정답 자세의 접촉 대비) | 0.72 | 0.72 | **0.81** |

(1280 px 상당: 바깥 카메라의 노이즈만 초점 거리 4 배로, 보이는지는 320 px 렌더로 판정.)

- **보이는 관절점**: 머리 카메라가 34 %, 세 시점 중 하나 이상이 42 %. 프레임의 46 % 는 어느 쪽도 4 점을 넘게 보지 못해 맞춤을 하지 않았다
  (손가락이 물건 뒤로 돌아가 있다). 머리 카메라에서 손이 물건을 가리는 비율 ρ_occ 은 평균 0.14 · 중앙 0 — 위에서 내려다보는 머리
  카메라에는 손이 물건 옆에 있다.
- **바깥 카메라는 멀어서 깊이가 거칠다**: 1.8 m 에서 σ_Z ≈ 6 cm 로 손가락 한 마디보다 크다. 정보 가중 융합은 그 방향을 거의 믿지 않으므로
  손목처럼 여러 점이 묶인 양은 좋아지지만, 머리 카메라가 못 본 손가락 끝은 바깥 카메라 한 대의 거친 깊이로만 정해진다. 해상도를 4 배로
  올리면(σ_Z ≈ 1.5 cm) 손가락 모양과 접촉도 좋아진다.
- **바닥**: 정답 점에 손 모델을 맞춘 잔차가 1.1 – 1.5 cm 다(들기 1.07 cm · 넣기 1.49 cm). 월드가 그리는 손은 손 프레임을 물건 면에
  맞춰 돌린 그림이라 모델의 강체 + 관절각으로 정확히 되지 않는다. 그래서 1 cm 아래의 PA-MPJPE 차이는 이 벤치로 가를 수 없다.

## 3. 지시문 주장 대조

| 지시문 | 코드 · 측정으로 확인한 것 |
|---|---|
| Σ_c = R_{W←c}[σ_Z² uuᵀ + (Zσ_θ)²(I − uuᵀ)]R_{W←c}ᵀ, u = (x − o)/‖x − o‖ | **식이 섞였다**: u 를 월드 좌표로 정의했으므로 괄호 안이 이미 월드 공분산이고, R 로 다시 돌리면 두 번 돈다. u 가 카메라 좌표일 때만 R 이 필요하다 → 월드 좌표 그대로 구현 |
| `SGBM_SUBPIXEL_PX` = 0.27 px 은 `noto_vision::sgbm`의 상수 | 값은 맞고 위치는 `noto_runtime::stereo` |
| 외부 고정 카메라 M 대로 연속 추적 | 엔진에 없다. 렌더러가 임의 시점을 그리므로 벤치에서 두 대를 둠 |
| MCP 외전 [−20°, 20°] | 손 모델은 ±15° (`hand::joint_spec`); 굽힘 한계 90 · 100 · 80° 는 같다 |
| Stage 1 결과를 `stop_gradient`로 동결 | 이 엔진에 자동 미분이 없다. 동결은 Stage 2 가 Stage 1 의 출력만 읽고 되돌려 쓰지 않는 것으로 |
| 패드 탄성층 4.5 mm, `MAX_ACTIVE_PADS` = 12 | 맞다 (`material::PAD_THICKNESS_M`, `contact::MAX_ACTIVE_PADS`) |
| `pad_indentation_m`이 간극에서 압입을 낸다 | 엔진의 그 함수는 힘 → 압입(Hertz 접촉 반경 → δ = a²/R, 유한 두께 포화)이다. 간극 → 압입 → 힘은 그 역(`tactile::hertz_force_n`, 시험으로 왕복 확인) |
| 고착비 φ = (1 − min(u, 1))^(2/3) | 맞다 (`contact::stick_ratio`, Cattaneo–Mindlin) |
| `GRIP_SAFETY` = 1.35 | **틀림**: 2.0 (`balance::GRIP_SAFETY`) |
| 결합 구동 λ_c = τ_in·max(0, J·r)/Σ(J·r)², 관절 정격 안 | 이미 `sim::top_grasp_shaped`에 있다(정격을 넘으면 비례 축소) |
| 손가락이 적은 손은 `statics_at`의 모멘트 평형으로 내분점 재할당 | `statics_at`은 공동 운반의 하중 정역학(`act::cocarry`)이다. 재할당은 힘 가중 중심(총 힘 보존, 평행한 힘이면 모멘트도)으로 구현 |
| `noto_core::dynamics`의 1차 지연 시정수 τ_servo | **틀림**: 계산 토크 제어(기준의 가속도 · 속도를 앞먹임, 4 Hz 임계 감쇠 PD)라 모델이 맞으면 지연 없이 따라간다. 고정 지연은 균형 보정의 `REACTION_DELAY_S` 0.10 s. 위상 선행 라벨은 1차 지연 서보에서만 정확한 역이다(§2) |
| 균일 중립 배경 [185, 188, 192] | 렌더러에 그런 배경은 없었다(빗나간 광선은 하늘 그라데이션) → `NEUTRAL_BG`로 추가 [추정] |
| `render_rays`에 `robot: &[]`면 정확한 배경 | 동료 · 탑승자 상자는 `render_rays`가 스스로 더하므로 그것까지 빼야 한다(`render_scene_only`) |
| 공유 3D RoPE 결합 어텐션 | 영상 생성 모델이 없어 해당 없음 |
| 1인칭이 가려지면 외부 시점으로 연속 추적 | 손목은 그렇다(−32 %). 손가락 끝은 바깥 카메라의 깊이가 손가락보다 거칠면(1.8 m · 320 px) 나아지지 않는다 (§1) |
| `ui/js/focus-view.js`에 촉각 스트림 | 바꾸지 않았다: 런타임은 손 상태를 시뮬레이터에서 알고 시각으로 손 자세를 추정하지 않으므로, 화면에 띄울 추정 스트림이 아직 없다 |

- noto-core: `fit3`(유사 변환이 축척 · 회전을 되돌림, 강체 맞춤은 축척 1), `handfit`(정확한 점이면 자세 복원 · 가려진 손끝도 모델이
  채움, 관절 한계 · 비틀림 0 · 경첩 벌림 0, 정보 행렬 가중이 한 방향으로 나쁜 점을 막음), `tactile`(닫힌 손의 누르는 패드 = 접촉, 편 손은
